# OKF convention & deterministic docs/ bundle indexes

## Why

The one map of the spec corpus — the hand-maintained table in `docs/specifications/README.md` — already drifts: it lists specs by hand, so it silently lies the moment someone forgets to update it. This specification adopts the **Open Knowledge Format** (OKF) as the convention for the whole `docs/` tree and replaces every hand-maintained bundle listing with a **deterministically generated `index.md`** — so the map is always true because it is derived, never authored. (The grounding layer that *consumes* this convention — feeding the OKF `docs/` tree into authoring/review — is the sibling [SPEC-027](027.okf-grounding-layer.md); this spec is the convention + the index machinery only.)

## What changes

- ADDED spec-library — `docs/` follows the **OKF convention**: per-document `type` frontmatter, per-folder `index.md`, markdown links — adopted as *format, not platform* (plain markdown in git, no runtime/SDK/service dependency).
- ADDED spec-library — **every `docs/` bundle gets a deterministically generated `index.md`** (specifications, decisions, design, …): a projection of each bundle's document frontmatter, kept current by a `docs/` filesystem watcher + a project-open sweep, with the spec lifecycle ops as a synchronous fast-path. No `index.md` is ever authored or maintained by an agent (non-negotiable #4 — projections are deterministic code).
- MODIFIED spec-library — the hand-maintained per-spec table migrates out of `README.md` into the generated `docs/specifications/index.md`, **preserving** its curated columns; the README keeps only human narrative and links to the generated map.
- ADDED spec-library — the OKF convention is taught once in `AGENTS.md` (and its `CLAUDE.md` mirror): `docs/` folders are OKF bundles, each has a **generated** `index.md` that must not be hand-edited.

**Depends on:** SPEC-020 (`createSpec`, `renderBlankSpec`), SPEC-024 (`commitStatus`, `approveDraft`). Builds on the pure `parseFrontmatter`/`parseSpecDoc` helpers (`contracts/src/spec-doc.ts`). **Depended on by:** SPEC-027 (the grounding layer consumes this convention and the generated spec-index digest).

## Requirements

### Requirement: `docs/` follows the OKF convention
`capability: spec-library` · `delta: ADDED (feat/spec-026-okf-bundle-indexes)`

The **entire `docs/` tree** SHALL follow OKF — every knowledge subfolder (`docs/specifications/`, `docs/decisions/`, `docs/design/`, `docs/analysis/`, …) is an OKF bundle, and there is **no dedicated folder per concern** (grounding included); documents live wherever they naturally belong and are found by their `type`, not their location. Every *authored* document carries YAML frontmatter with at least a `type` field, concepts interlink via ordinary markdown links, and each bundle folder has an `index.md` entry point. The `type` vocabulary is **open** — a document may carry a `type` outside the known set and SHALL be accepted, not rejected; the known set (`specification` · `product-overview` · `business-context` · `domain-glossary` · `architecture` · `convention` · `index`) is advisory, used for framing/injection, never as a validation gate. Readers SHALL be **tolerant**: a document that predates the convention and lacks `type` SHALL NOT fail parsing — its `type` is derived (a file bearing a `spec_id` under `docs/specifications/` is `specification`; a folder `index.md` is `index`; anything else with no `spec_id` is treated as `convention`). New specs SHALL be OKF-well-formed **by construction from the actual scaffold path**: since `createSpec` writes from the hardcoded `renderBlankSpec()` string (NOT the template file), `renderBlankSpec` SHALL emit `type: specification`; `specification.template.md` SHALL also gain it for hand-authored specs. The convention is adopted as **format, not platform** — no OKF runtime, SDK, or external service is a dependency.

#### Scenario: A coordinator-created spec is OKF-well-formed
- **WHEN** a specification is scaffolded via `createSpec` (which renders `renderBlankSpec`)
- **THEN** its frontmatter carries `type: specification` alongside the existing `spec_id`/`status`/`branch` fields

#### Scenario: A legacy document without `type` still parses
- **WHEN** the reader encounters a `docs/specifications/*.md` file with no `type` field but a `spec_id`
- **THEN** it is treated as `type: specification` (derived), not rejected

#### Scenario: An unknown type is accepted, not rejected
- **WHEN** a document declares a `type` outside the known set
- **THEN** it is accepted (framed generically); no validation error is raised

### Requirement: Every `docs/` bundle index is generated deterministically, never by an agent
`capability: spec-library` · `delta: ADDED (feat/spec-026-okf-bundle-indexes)`

**Every** OKF bundle under `docs/` — `docs/specifications/`, `docs/decisions/`, `docs/design/`, `docs/analysis/`, and any other subfolder containing OKF markdown (plus the `docs/` root if it holds top-level documents) — SHALL have an `index.md` that is a **deterministic projection** of that bundle's documents' frontmatter. No bundle `index.md` is ever hand-authored or agent-authored. A "bundle" is any `docs/` directory containing at least one OKF markdown document; a directory with none (e.g. `docs/assets/`) gets no index.

**Coverage is deterministic for all bundles via three layers:**
1. **Filesystem watcher** — the coordinator watches `docs/**` and, on any add / change / delete / rename of a bundle document, regenerates *that bundle's* `index.md` (debounced ~250 ms). The generator's own writes to an `index.md` SHALL be excluded from the watch so regeneration cannot self-trigger a loop.
2. **Startup + project-open sweep** — the coordinator regenerates every bundle's `index.md` when a project context starts, so indexes are correct after out-of-band edits, a `git pull`, or edits made while the coordinator was down.
3. **Spec lifecycle fast-path** — because `docs/specifications/` status is written through coordinator ops, `createSpec` / `renameSpec` / `commitStatus` / `approveDraft(Locked)` SHALL regenerate the specs index **synchronously** (not on watcher latency), so a governed status write reflects immediately. This matters because the `draft → in-review` promotion is written by `approveDraft` directly and does **not** pass through `commitStatus` (`applyTransition` delegates that edge to it); all four are wired. For non-spec bundles the watcher + sweep are the whole mechanism.

**Per-bundle rendering.** The generator is bundle-aware. `docs/specifications/` renders the rich spec table (number, title, status, capabilities + the curated PRD-coverage / phase / points columns; ordered by numeric `NNN` with a filename tiebreak; selecting only `^\d{3}\.` files, excluding `README.md` / `specification.template.md` / `index.md` / `examples/`). Every **other** bundle renders the generic OKF index — one row per document: its `type`, `title`, a one-line description (frontmatter `description`, else the first paragraph after the frontmatter), and a relative link; ordered by title then filename; excluding the folder's own `index.md`, any `README.md`, and templates.

**Determinism, per bundle.** Each `index.md` SHALL be regenerated by a pure, total rescan-and-rewrite (never incremental) so it is **idempotent** — a no-op regeneration yields a byte-identical file and no git diff. To keep that true, a generated `index.md` SHALL carry no wall-clock timestamp (any date is derived purely from indexed content), and every generated `index.md` SHALL be pinned to LF via `.gitattributes` (`docs/**/index.md text eol=lf`) with the generator writing LF, so an autocrlf checkout cannot create a perpetual diff. Each generated file carries a machine marker (`generated: true` + a "do not edit by hand" HTML-comment banner). Generation is robust and never blocks its trigger: a document that is unparseable — unterminated frontmatter, malformed YAML array, missing required field (`spec_id`/`title` for specs; a derivable `title`/`type` for others), or an out-of-enum `status` — SHALL be listed with a `⚠ unparsed` marker (see the entry shapes in Design), not throw. Since `parseFrontmatter` returns arrays as raw strings, the generator SHALL parse flow-sequences (`[a, b, …]`) into `string[]` itself. **No agent, prompt, or harness path SHALL write any `index.md`.**

#### Scenario: Creating a spec refreshes the specs index synchronously
- **WHEN** `createSpec` writes a new specification file
- **THEN** `docs/specifications/index.md` is regenerated to include it (ordered by `NNN`), synchronously, with no agent turn involved

#### Scenario: The draft→in-review promotion refreshes the status column
- **WHEN** a draft is promoted to `in-review` via `approveDraft` (the edge that bypasses `commitStatus`)
- **THEN** the specs index status column for that spec reads `in-review`

#### Scenario: Editing a NON-spec bundle refreshes THAT bundle's index
- **WHEN** a document is added to or edited in `docs/decisions/` (or any non-spec bundle)
- **THEN** the watcher regenerates `docs/decisions/index.md` to reflect it — no coordinator op and no agent turn involved

#### Scenario: Startup sweep repairs out-of-band edits
- **WHEN** a project context starts after bundle documents changed while the coordinator was down (or were pulled from git)
- **THEN** the sweep regenerates every bundle's `index.md` to match the on-disk documents

#### Scenario: The generator does not self-trigger
- **WHEN** regeneration writes a bundle's `index.md`
- **THEN** that write does not trigger another regeneration (index files are excluded from the watch)

#### Scenario: No-op regeneration is byte-identical (any bundle, incl. across days and autocrlf)
- **WHEN** any bundle's index is regenerated and none of its documents changed
- **THEN** the file is byte-identical and produces no git diff — including on a later calendar day and under an autocrlf checkout

#### Scenario: A malformed document is flagged, not fatal
- **WHEN** one document in a bundle has unterminated frontmatter, a malformed array, or a missing required field
- **THEN** it appears with an `⚠ unparsed` marker carrying its filename; every other document still appears; regeneration succeeds

#### Scenario: Non-document files are excluded
- **WHEN** a bundle also contains `README.md`, a template, its own `index.md`, or (specs) an `examples/` subtree
- **THEN** none of them appears as a row in the generated index

### Requirement: The OKF convention is taught once, durably, in AGENTS.md (and its mirror)
`capability: spec-library` · `delta: ADDED (feat/spec-026-okf-bundle-indexes)`

The agent SHALL NOT need to know "OKF" as a named standard — the artefacts are self-describing markdown. The convention SHALL be captured once, durably, in `AGENTS.md`: a short house-rules section stating that `docs/` folders are OKF bundles, each has an `index.md` to consult, related documents are reached by following links, and — critically — **the index is generated and MUST NOT be hand-edited**. Because `CLAUDE.md` mirrors `AGENTS.md` (PRD §12.2), the same section SHALL be reflected in `CLAUDE.md` (or the mirror regenerated) so the two do not drift. No per-turn "explain OKF" prompt scaffolding SHALL be added.

#### Scenario: The convention rides on existing grounding, mirror included
- **WHEN** AGENTS.md is injected into a session
- **THEN** it carries the OKF house-rules section (including that `index.md` is generated, not hand-edited), and `CLAUDE.md` reflects the same guidance

## Design

### Architectural decision

Each bundle index is a **deterministic projection of the bundle's frontmatter** (non-negotiable #4). Because non-spec bundles have no coordinator write-path, coverage is a `docs/**` watcher + a project-open sweep, with the spec lifecycle ops kept only as a synchronous fast-path (the `draft → in-review` edge is written by `approveDraft`, bypassing `commitStatus`). OKF is adopted as **format, not platform**. Code is referenced by symbol name because the coordinator source drifts under concurrent authoring.

### Target architecture

- **Pure generators in `@arke/contracts`** — `renderSpecIndex(entries)` (the rich spec table) and `renderBundleIndex(bundle, entries)` (the generic OKF table: `type · title · description · link`), peers to the pure `spec-doc.ts` helpers. Both deterministic (stable order + filename tiebreak, LF, generated banner, content-derived non-wall-clock date, `⚠ unparsed` rows) ⇒ idempotent + unit-testable.
- **Coordinator wiring** — `ProjectContext.regenerateBundleIndex(dir)` scans one bundle, parses each doc via `parseFrontmatter` (splitting flow-sequence arrays from their raw string), classifies parse failures, and writes that bundle's `index.md` via the right generator. **Three drivers keep every bundle current:** (1) a debounced `docs/**` watcher (chokidar-style; `index.md` writes excluded); (2) `sweepAllBundles()` on project-context start; (3) the spec lifecycle ops → synchronous `regenerateBundleIndex(docs/specifications)`. All best-effort: a failure is traced and swallowed, never thrown into the caller.
- **Trace** — each regeneration appends an `index.generated` record `{ bundle, trigger, docCount, changed, path, error? }`. `Trace.write(record: Record<string, unknown>)` permits this with no contract change; regeneration uses best-effort `write()` (never `writeOrThrow`).

### Data model

- **`type` vocabulary (open):** `specification` · `product-overview` · `business-context` · `domain-glossary` · `architecture` · `convention` · `index`. Only `type` is required; unknown types are accepted.
- **`SpecIndexEntry`** (the `docs/specifications/` bundle) — discriminated so unparsed rows need no invented data:
  - parsed: `{ parseState: "ok"; number; specId; title; status: SpecStatus; capabilities: string[]; path }`
  - unparsed: `{ parseState: "unparsed"; number?; filename; path; error }`
- **`BundleIndexEntry`** (every other bundle):
  - parsed: `{ parseState: "ok"; type; title; description?; path }`
  - unparsed: `{ parseState: "unparsed"; filename; path; error }`
- **`index.md` shape:** frontmatter `type: index`, `generated: true`, content-derived date only; a "generated — do not edit by hand" banner. `docs/specifications/` preserves the README's curated columns — `# | Spec | Status | Capabilities | Covers (PRD) | Phase | ~pts`; other bundles use `Type | Title | Description`. `⚠ unparsed` rows show filename + error.

### Cross-cutting

- **Determinism / idempotence:** whole-file rewrite + stable order + content-derived date + LF via `.gitattributes` ⇒ byte-identical no-op output across days and autocrlf checkouts.
- **Performance:** regeneration is O(n) over a bundle's files; negligible.
- **Design template:** any UI touch follows the `arke-design` skill; this slice is coordinator + docs.

## Tasks

### Phase A — the deterministic index engine
- [ ] `@arke/contracts`: `SpecIndexEntry` + `BundleIndexEntry` (each parsed | unparsed); pure `renderSpecIndex()` (rich table, preserved curated columns) and `renderBundleIndex()` (generic `type · title · description · link`) — stable order + filename tiebreak, LF, generated banner, content-derived date, `⚠ unparsed` rows.
- [ ] Coordinator: `regenerateBundleIndex(dir)` — scan one bundle, parse via `parseFrontmatter` (split flow-sequence arrays), classify unparsed, pick spec-vs-generic generator, best-effort write + `index.generated` trace.
- [ ] Coverage drivers: a debounced `docs/**` watcher (exclude `index.md` writes); `sweepAllBundles()` on project-context start; the spec lifecycle fast-path (`createSpec`/`renameSpec`/`commitStatus`/`approveDraft(Locked)`).
- [ ] `.gitattributes`: `docs/**/index.md text eol=lf`.
- [ ] Tests: pure generators (order, tiebreak, idempotence incl. next-day + CRLF, unparsed, exclusions); integration (spec choke-points refresh synchronously incl. draft→in-review; watcher refreshes a non-spec bundle; startup sweep repairs out-of-band edits; no self-trigger; malformed doc non-fatal).

### Phase B — convention & docs
- [ ] OKF house-rules section in `AGENTS.md` **and** reflected in `CLAUDE.md` (mirror, no drift).
- [ ] `renderBlankSpec` emits `type: specification`; `specification.template.md` gains it too.
- [ ] Migrate the per-spec table from `docs/specifications/README.md` into the generated `index.md`, **preserving** Covers-PRD/Phase/~pts and curated titles (carried as generator inputs — see Open questions); README keeps narrative + a link to the generated map.

### Testing
- Unit: both generators — order/tiebreak, byte-identical idempotence (same input, next day, CRLF), unparsed rows, exclusions, preserved columns.
- Integration: each spec choke-point regenerates synchronously; draft→in-review updates status; watcher covers a non-spec bundle; startup sweep; no self-trigger; malformed non-fatal.
- Manual: `index.md` renders on GitHub; AGENTS.md + CLAUDE.md carry the house rules.

### Definition of done
- All scenarios pass; `npm run typecheck` + `npm run build` green for touched packages.
- Every `docs/` bundle has a generated `index.md` (specs = rich table with preserved curated columns; others = generic), each byte-stable on no-op (incl. next-day + autocrlf) and carrying the do-not-edit banner.
- Indexes stay current via the `docs/**` watcher + project-open sweep, with the spec lifecycle ops as a synchronous fast-path; regeneration never self-triggers.
- No agent/prompt/harness path writes any `index.md`.

## Decision log
| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Indexes generated, never agent-maintained | Non-negotiable #4; a stale hand/agent index lies |
| 2 | **Four** spec choke-points incl. `approveDraft` | `draft → in-review` is written by `approveDraft`, bypassing `commitStatus`; three points would leave the status column stale at the most common first move (both review reviewers, blocking) |
| 3 | No wall-clock date in `index.md`; content-derived; LF via `.gitattributes` | Preserve byte-identical idempotence across days and autocrlf checkouts (both reviewers, blocking) |
| 4 | Entries are parsed \| unparsed; explicit unparsed criteria | `parseFrontmatter` is tolerant (returns `{}`, doesn't throw), so "malformed" needs its own definition rather than invented fields (reviewer-b, blocking) |
| 5 | Reference code by symbol name, not line numbers | The source drifts under concurrent authoring; the review flagged already-drifted anchors (reviewer-a, blocking ×3) |
| 6 | `type` vocabulary is open; validation advisory | Resolves the open-vs-closed contradiction |
| 7 | Preserve README's curated columns | Naive migration would drop PRD-coverage/phase/points/titles — a regression (reviewer-a, blocking) |
| 8 | Cover **ALL** `docs/` bundles via watcher + sweep | Whole-`docs/` OKF ⇒ every bundle needs a generated index; non-spec bundles have no coordinator write-path, so a watcher + sweep is the deterministic mechanism |
| 9 | Split out the grounding layer to SPEC-027 | v1 combined index generation (`spec-library`) with grounding (`grounding`) — two independent capabilities in one spec, ~13–16 pts. The README's rule is "slices follow capability boundaries"; this is the spec-library half |

## Open questions
- **Curated columns' source of truth.** Covers-PRD / Phase / ~pts are not in spec frontmatter today. Options: (a) add `covers`/`phase`/`points` to spec frontmatter so the generator derives everything — cleanest, but touches every spec; (b) keep a small hand-maintained side-file the generator merges. Leaning (a), backfilled opportunistically; until then those columns may be omitted for un-backfilled specs. **The one remaining hand-authored surface to eliminate.**
- **Watcher availability.** All-bundle coverage leans on a `docs/**` watcher in a long-running coordinator. In headless/CI/packaged contexts the project-open sweep + an explicit `okf.reindex` op are the fallback; the watcher SHALL degrade to sweep-only rather than fail. Debounce window and the exact bundle-detection rule are Phase-A implementation details.
- Should a malformed-doc `⚠ unparsed` row also raise a `spec.malformed`-style event (SPEC-024) for visibility, or is the index marker enough?
