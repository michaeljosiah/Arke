# Omnigent meta-harness — from spike to production substrate

## Why

`@arke/adapter-omnigent` is the ADR-0002 spike: it proved the substrate thesis — a real OpenCode turn was
driven end-to-end through Omnigent's v1 HTTP API behind the neutral `HarnessAdapter` seam — but it is kept
**off the default composition** pending hardening. Omnigent is a **meta-harness**: one backend-agnostic
control plane over ~15 concrete harnesses (OpenCode, Claude Code, Codex, Cursor, Goose, …), with a
server/runner split that mirrors Arke's own coordinator/runner model (SPEC-018). Promoting it off the spike
lets an Arke agent **role run on whichever substrate serves the model it needs** — the payoff the neutral
seam was built for — while Arke keeps authority over the roster (harness-agnostic images + logical tiers,
ADR-0004).

A live probe against **Omnigent 0.3.0** (this spec's grounding) surfaced the concrete gaps. The most
important is a **correctness** one, not just resilience: the spike's `normalize()` was written against
OpenAI-Responses shapes (`response.output_text.delta`, `response.completed`, nested `data.*`), but the live
server emits a different envelope — `{ sequence_number, type, … }` with `session.*` / `response.*` frames
(`session.status`, `session.heartbeat`, `session.input.consumed`, `response.error`, elicitation frames). The
spike normalizes against shapes the live server does not send. Beyond that, the spike has no
event-confirmed approvals, no reconnect, no correlation matching, and an in-memory-only session map — the
four production gaps named in the PRD (correlation, event-confirmed approvals, reconnect, version pinning).

## What changes

- ADDED omnigent-substrate — the adapter's `normalize()` is **re-grounded on the real Omnigent 0.3.0 event
  envelope** (`{ sequence_number, type }` with `session.*`/`response.*` frames), captured live and pinned as
  a fixture, so it emits correct `DomainEvent`s instead of matching shapes the server never sends.
- ADDED adapter-resilience — **event-confirmed approvals** (a permission decision is only `confirmed` once
  the stream echoes its resolution), **correlation matching** (the `item_id` that `POST …/events` returns is
  matched against the `session.input.consumed` frame that echoes it), **reconnect + backfill** (on stream
  close, reconnect with backoff and replay missed frames using the monotonic `sequence_number`), a **durable
  session store** (survives an adapter restart), and a **dead-letter sink** (an unmapped frame is recorded,
  never silently dropped).
- ADDED harness-integration — **completion-aware `sendMessage`** (resolves when the turn reaches
  `session.status: idle`, so a synchronous caller works), **`listModels()`** (best-effort, from the host's
  configured harnesses / model catalog; `models` capability added when available), and **version pinning**
  (the adapter targets a pinned Omnigent version, validates `/api/version` at `init`, and refuses/`warn`s a
  mismatch instead of failing obscurely on a drifted alpha API). The adapter is then **added to the default
  composition** behind the existing registry gate (a connect still verifies readiness — SPEC-019).
- Out of scope for v1 (named follow-ups, ADR-0004): `getDiff`/`getTodos`/`runCommand`/`revert`/`unrevert`
  and `materializeAgent` — Omnigent exposes endpoints for these (`…/environments/{id}/changes`, `…/shell`,
  `…/fork`), but they are additive; the adapter continues to declare only the capabilities it truly supports.

## Requirements

### Requirement: The normalizer matches the real Omnigent event envelope
`capability: omnigent-substrate` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

`normalize()` SHALL map the **actual** Omnigent 0.3.0 stream envelope — a flat frame `{ sequence_number,
type, … }` — onto Arke `DomainEvent`s, driven by a fixture of **live-captured** frames (not synthetic
OpenAI-Responses shapes). It SHALL map: `session.status` (`running`/`idle`/`failed`) → `session.status`;
the assistant-content frames → `message.part` (streaming delta) and `message.updated` (snapshot);
`response.error` (carrying `error.code`/`error.message`) → `session.status: error`; the elicitation-request
frame → `permission.asked`. Non-domain control frames (`session.heartbeat`, `session.presence`,
`session.changed_files.invalidated`, `session.terminal_pending`) SHALL be recognised and ignored (not
dead-lettered). A frame whose `type` is unrecognised SHALL be dead-lettered (Requirement: dead-letter),
never silently dropped. The normalizer stays a **pure function** of `(frame, state) → DomainEvent[]`.

#### Scenario: A live status frame maps to a session status
- **WHEN** the stream yields `{ type: "session.status", status: "idle", conversation_id }`
- **THEN** `normalize()` emits a `session.status` domain event for that session with a quiescent/idle status
- **AND** a `session.status` with `status: "failed"` and an `error` maps to `session.status: error` carrying the code/message

#### Scenario: A heartbeat is ignored, an unknown frame is dead-lettered
- **WHEN** the stream yields a `session.heartbeat` frame
- **THEN** `normalize()` returns no domain events and the frame is NOT recorded as unmappable
- **AND** WHEN a frame carries an unrecognised `type`, it is surfaced to the dead-letter sink, not dropped

### Requirement: A permission decision is confirmed by a stream event, not the HTTP ack
`capability: adapter-resilience` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

`respondToPermission()` SHALL resolve the elicitation over HTTP (`POST …/elicitations/{id}/resolve`) and
then MUST return `confirmed` **only after** the event stream reflects the resolution for that elicitation id
(the 202 HTTP ack alone is NOT confirmation — only events are authoritative, SPEC-002). It SHALL return
`stale` for an unknown/already-resolved elicitation id, `duplicate` for a repeated decision on the same id,
and time out to `unconfirmed` (bounded wait) if no confirming event arrives — the same disposition set the
OpenCode adapter's permission coordinator uses. A confirming event that arrives after the timeout SHALL not
throw (it is reconciled or ignored).

#### Scenario: A resolved elicitation confirms on the event
- **WHEN** `respondToPermission({ permissionId, decision: "once" })` posts the resolve and the stream then
  reflects that elicitation resolved
- **THEN** the call returns `status: "confirmed"`

#### Scenario: No confirming event within the bound
- **WHEN** the resolve is accepted (202) but no confirming event arrives within the timeout
- **THEN** the call returns `status: "unconfirmed"` (never a false `confirmed`), and a later confirming event does not throw

### Requirement: Outbound messages are correlated to their stream frames
`capability: adapter-resilience` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

`sendMessage()`/`dispatchAsync()` SHALL capture the `item_id` that `POST …/events` returns
(`{ queued: true, item_id }`) and use it as the turn's correlation key, matched against the
`session.input.consumed` frame whose `data.item_id` echoes it. Every `DomainEvent` the adapter emits for that
turn SHALL carry a stable `correlationId` derived from this mapping (caller-supplied `correlationId` is
preserved when given), so the coordinator can tie a stream event back to the message that caused it — the
spike's best-effort correlation is replaced by an id the server actually echoes.

#### Scenario: The consumed frame echoes the outbound item id
- **WHEN** `POST …/events` returns `item_id: X` and the stream later yields `session.input.consumed` with `data.item_id: X`
- **THEN** the adapter binds that turn's correlationId to `X` and stamps it on the turn's emitted events

### Requirement: The stream reconnects and backfills missed frames on disconnect
`capability: adapter-resilience` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

The per-session stream pump SHALL detect a closed/errored SSE stream and **reconnect with bounded
exponential backoff** rather than dying silently (the spike stops on first error). On reconnect it SHALL use
the monotonic `sequence_number` to **detect a gap** and **backfill** the missed frames (from the session
history/items REST endpoint, or a resume-from-sequence parameter if the server supports it), emitting the
recovered `DomainEvent`s in order and without duplication. Reconnect SHALL be bounded (a max attempt/So
window) and, on exhaustion, surface a terminal `session.status` degradation rather than hang. A reconnect
that recovers SHALL not re-emit already-delivered events (idempotent by `sequence_number`).

#### Scenario: A dropped stream reconnects and replays the gap
- **WHEN** the SSE stream closes mid-session after sequence N and later frames exist up to sequence N+k
- **THEN** the pump reconnects, backfills sequences N+1..N+k in order, and resumes live streaming
- **AND** no event already delivered before the drop is emitted a second time

#### Scenario: Reconnect exhaustion is terminal, not a hang
- **WHEN** reconnection fails past the bounded attempt window
- **THEN** the adapter emits a terminal degraded `session.status` for the session and stops retrying (no silent hang)

### Requirement: Session identity survives an adapter restart, and unmapped frames are recorded
`capability: adapter-resilience` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

The adapter's session graph (Omnigent session id → Arke `{ specId, kind }`) SHALL be **durable** — persisted
so an adapter/coordinator restart re-attaches streams to their specs instead of losing the mapping (adopting
the OpenCode adapter's file-backed session store). Every stream frame the normalizer cannot map SHALL be
routed to a **dead-letter sink** (recording the frame `type` + a bounded snapshot) so unhandled shapes are
diagnosable in the trace, never silently swallowed (SPEC-015 observability).

#### Scenario: Identity re-attaches after a restart
- **WHEN** the adapter is restarted while sessions are live
- **THEN** it re-loads each session's `{ specId, kind }` from the durable store and re-attaches its stream

#### Scenario: An unmapped frame lands in the dead-letter sink
- **WHEN** the stream yields a frame whose `type` the normalizer does not handle and which is not a known-ignored control frame
- **THEN** the frame is recorded to the dead-letter sink with its type, and processing of subsequent frames continues

### Requirement: Synchronous send completes on the turn's quiescence, and the adapter pins its Omnigent version
`capability: harness-integration` · `delta: ADDED (feat/spec-037-omnigent-substrate)`

`sendMessage()` SHALL resolve when the turn reaches quiescence (`session.status: idle`/completion for that
turn's correlationId), so a synchronous caller does not have to poll the event stream (matching the Codex
adapter's completion-aware send); `dispatchAsync()` remains fire-and-watch. `init()` SHALL read the server
version (`GET /api/version`) and validate it against the **pinned** Omnigent version the adapter targets; on
an incompatible version it SHALL surface a readiness warning/refusal (fail loud) rather than proceed against
a drifted alpha API. `listModels()` SHALL be provided on a best-effort basis from the host's configured
harnesses / model catalog, and the `models` capability declared only when it returns a real catalog;
credentials remain **host-side** and never cross the adapter's return values (NFR-1, unchanged from the
spike's `OmnigentConfig`).

#### Scenario: A synchronous send waits for quiescence
- **WHEN** `sendMessage()` posts a turn
- **THEN** it resolves once that turn's `session.status` reaches idle/completion, not on the bare 202

#### Scenario: A version mismatch is surfaced, not swallowed
- **WHEN** `init()` finds the server's `/api/version` outside the adapter's pinned/supported range
- **THEN** readiness reports the mismatch (not `ready: true`), so the coordinator does not silently drive a drifted API

## Design

### Architectural decision

Keep the spike's shape — a thin `HarnessAdapter` over Omnigent's v1 HTTP API with a pure `normalize()` and a
per-session SSE pump fanned into one `EventChannel` — and **harden the seams that a live 0.3.0 run proved
wrong or missing**, rather than rewrite. The single highest-value change is re-grounding `normalize()` on the
real event envelope, captured live and frozen as a fixture, because the spike matches shapes the server does
not emit. The resilience layer (confirmed approvals, correlation, reconnect+backfill, durable store,
dead-letter) is adopted from the **already-proven patterns** in `@arke/adapter-opencode` (permission
coordinator, file session store, reconnect/backoff, dead-letter) and `@arke/adapter-codex` (completion-aware
send via turn waiters, fake-transport tests), so Omnigent reaches the same production bar those adapters set.
Arke's authority is unchanged (ADR-0004): the roster stays harness-agnostic; the adapter only projects down
(`model_override`), and credentials never leave the host.

### Target architecture

- **`packages/adapter-omnigent/src/normalize.ts`** — rewritten switch over the real `type` vocabulary
  (`session.status`, assistant-content frames, `response.error`, elicitation-request, known-ignored control
  frames), keyed off `{ sequence_number, type }`; still `(frame, state) → DomainEvent[]`. A committed fixture
  of **live-captured** frames (`test/fixtures/omnigent-0.3.0-frames.jsonl`) is the ground truth.
- **`packages/adapter-omnigent/src/index.ts`** —
  - `PermissionCoordinator`-style confirm-by-event for `respondToPermission()` (timeout + stale + duplicate),
    fed by the pump recording elicitation-resolution frames.
  - Correlation map `itemId ↔ correlationId`, populated from the `POST …/events` response and matched on
    `session.input.consumed`; stamped onto emitted events.
  - `pump()` gains **reconnect with bounded backoff** + **sequence-gap backfill** (REST history / resume),
    idempotent by `sequence_number`; on exhaustion emits a terminal degraded status.
  - `TurnWaiters` so `sendMessage()` resolves on the turn's quiescence.
  - `DeadLetterSink` for unmapped frames.
- **`packages/adapter-omnigent/src/session-graph.ts`** — a file-backed `FileSessionStore` (adopting the
  OpenCode pattern) so identity survives a restart.
- **`packages/adapter-omnigent/src/config.ts`** — a pinned `OMNIGENT_TARGET_VERSION`; `init()` validates
  `/api/version`. **`http.ts`** unchanged in shape (Bearer host-side, abort timeout).
- **Composition/registry** — the adapter is registered in the default harness composition; the SPEC-019
  connect flow still gates on a verified readiness (which now includes the version check).

### Interfaces and contracts

- `HarnessAdapter` is unchanged. The adapter's declared `capabilities()` stays `{ events, permissions }`,
  adding `models` iff `listModels()` returns a real catalog. `respondToPermission()` now returns a
  disposition that reflects event confirmation (`confirmed`/`unconfirmed`/`stale`/`duplicate`).
- The live-frame fixture is the interface-of-record for `normalize()`; changing it requires a re-capture.

### Cross-cutting

- **Security (NFR-1):** the Omnigent token stays in `OmnigentConfig` host-side and is never returned or
  logged; model credentials live in the runner (the OpenCode `auth.json`), never on the Arke wire — unchanged.
- **Observability (SPEC-015):** the dead-letter sink + reconnect/version events are traced.
- **Resilience parity (SPEC-002):** confirmed approvals, reconnect + replay, and correlation bring Omnigent to
  the OpenCode adapter's resilience contract.
- **Alpha risk:** the pinned version + fail-loud mismatch + live-frame fixture bound the alpha-churn risk
  ADR-0002 flagged; the spike Dockerfile's `uv tool install omnigent` is pinned to the target version.

### Testing
- **Unit (fake transport, mirroring `@arke/adapter-codex`'s fake app-server):** `normalize()` over the real
  frame fixture (status → session.status; assistant frames → message.part/updated; `response.error` → error;
  elicitation → permission.asked; heartbeat ignored; unknown → dead-letter); confirm-by-event approval
  (confirmed / unconfirmed-on-timeout / stale / duplicate); correlation binding from `item_id` ↔
  `session.input.consumed`; reconnect + sequence-gap backfill with no duplicate emission; terminal degrade on
  exhaustion; durable store re-attach after restart; completion-aware send resolves on idle; version-pin
  mismatch → readiness refusal.
- **Live acceptance (gated on a reachable Omnigent + a valid runner credential):** one real turn end-to-end
  through the adapter (assistant output), one real elicitation confirmed by event, and one forced reconnect
  that replays the gap — the exit criterion that moves the adapter into the default composition. *(Blocked in
  this environment only by an expired OpenCode OAuth token — `Token refresh failed: 401`; the server + adapter
  path are otherwise live-verified.)*

### Definition of done
`normalize()` matches live Omnigent 0.3.0 frames (fixture-backed); approvals are event-confirmed; outbound
messages correlate to their stream frames; the pump reconnects + backfills without duplication; identity is
durable; unmapped frames are dead-lettered; `sendMessage()` is completion-aware; the version is pinned with a
fail-loud mismatch; the fake-transport suite is green with `typecheck` + `build`; the live-acceptance run has
passed (or is explicitly recorded as the remaining gate pending a runner credential); and a non-author
reviewer has signed off.

## Open questions
- Does Omnigent 0.3.0 expose a resume-from-`sequence_number` on `…/stream`, or must backfill read
  `…/items` history? v1: prefer a resume parameter if present, else replay from history filtered by sequence.
- Is there a first-class models endpoint, or is `listModels()` derived from the host's `configured_harnesses`
  + per-harness catalog? v1: derive best-effort; declare `models` only when it yields a real list.
- Should substrate-exclusivity (a role bound to Omnigent vs a direct leaf) surface as a distinct registry
  warning (SPEC-019 deferred it)? Out of scope here; revisit with the composition wiring.
