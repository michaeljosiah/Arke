# Agent-adjudicated review — the spec-author triages the panel, the human only approves

## Why

Today the multi-model review panel ([SPEC-007](007.multi-model-review-panel.md)) makes the human do two
jobs: **triage every reviewer issue** (accept / dismiss / send-back, one click per issue) *and* **approve
the specification**. The first job does not need a human. The reviewers already produce structured,
severity-tagged, section-anchored issues; deciding which to fold into the draft and revising the prose is
exactly the `spec-author` agent's competence. Keeping a human in the per-issue loop makes review a manual
bottleneck that scales with issue count, not with judgement.

This specification moves **adjudication** from the human to the `spec-author` agent, and collapses the
human's role to a single governed decision: **approve the finished specification** (or send it back). The
adversarial half of review is untouched — two reviewers still run in parallel, blind to each other,
read-only, on pairwise-distinct models. Only the *triage-and-revise* step changes hands.

## What changes

- MODIFIED review-panel — the per-issue human adjudication (`accept` / `dismiss` / `send-back` in
  `review-generation.tsx`) is replaced by an **author adjudication turn**: after a panel completes, the
  `spec-author` receives the working spec plus every reviewer issue (with severity and agreement marks) and
  returns a **per-issue disposition** — `accept` (apply the edit) or `dismiss` (recorded rationale) — then
  applies the accepted edits to the working file. The human no longer triages issues.
- ADDED review-panel — an **auto-review loop**, bounded at **3 rounds**: if an adjudication round accepts at
  least one **blocking** issue *and* the specification's normative content actually changes, a fresh panel
  reconvenes on the revised draft. The loop stops on convergence (no blocking issues, or a round that
  changes nothing) or at the round cap.
- ADDED review-panel — **accept-or-justify** on blocking issues: every `blocking` issue MUST be either
  accepted-and-applied or dismissed-with-recorded-rationale; a dismissed blocker is surfaced to the human at
  approval, never silently dropped.
- MODIFIED spec-lifecycle — the review gate ([SPEC-024](024.specification-lifecycle-gating.md)) is satisfied
  by **adjudication convergence**, not by mere panel completion; on convergence the coordinator auto-runs the
  gated `draft → in-review` promotion, so the human's sole governed action is `in-review → approved` (or
  send-back).
- ADDED review-panel — **adjudicator independence**: the adjudicating author's resolved model SHOULD differ
  from both reviewers; a collision is **warned and traced** (`panel.adjudicator-model-collision`), not
  silently ignored and not hard-blocked.

**Depends on:** SPEC-007 (review panel), SPEC-024 (lifecycle gating), SPEC-013 (generation workspace UI
surface), SPEC-027 (grounding digest the author receives).

## Requirements

### Requirement: The author adjudicates the panel, not the human
`capability: review-panel` · `delta: MODIFIED (feat/spec-035-agent-adjudicated-review)`

When a review panel completes with at least one successful reviewer, the coordinator SHALL dispatch a single
**adjudication turn** to the `spec-author` agent instead of waiting for human per-issue actions. The
adjudication turn SHALL receive: the current working specification text, the project grounding digest
(SPEC-027, same `groundingSummary()` the reviewers received), and **every** parsed issue from all reviewers
— each carrying its `reviewerRole`, `section`, `severity`, `text`, and whether it was marked `agreed` across
reviewers. The author SHALL return a **disposition for every issue**: `accept` or `dismiss`, each with a
short `rationale`. For every `accept`, the author SHALL apply the corresponding revision to the working file
(the write path stays singular — the author is the only writer, as in SPEC-007 Decision #4). The coordinator
SHALL record each disposition to the durable trace as `review.adjudicate { action, rationale, actor:
"spec-author", issueId, section, sectionHash }` and emit a `panel.disposition` event per issue. The former
human adjudication controls (`accept` / `dismiss` / `send-back` buttons) SHALL be removed from the primary
review flow.

#### Scenario: A completed panel triggers an author adjudication turn
- **WHEN** a panel reaches `complete` with at least one successful reviewer
- **THEN** the coordinator dispatches one `spec-author` adjudication turn carrying the working spec, the
  grounding digest, and all parsed issues
- **AND** no human per-issue action is required for the panel to progress

#### Scenario: Every issue receives a traced disposition
- **WHEN** the author adjudication turn returns
- **THEN** every issue has a recorded disposition of `accept` or `dismiss` with a rationale
- **AND** each disposition is written to the trace as `review.adjudicate { actor: "spec-author", … }` and
  emitted as `panel.disposition`

#### Scenario: Accepted issues are applied by the author only
- **WHEN** the author accepts an issue
- **THEN** the resulting edit to the working file is made by the `spec-author` agent, not by a reviewer
- **AND** the reviewer that raised the accepted issue is recorded in the trace as its source

### Requirement: A bounded auto-review loop
`capability: review-panel` · `delta: ADDED (feat/spec-035-agent-adjudicated-review)`

Review SHALL run as a loop of at most **3 rounds**. Each round convenes a panel (SPEC-007) and runs one
author adjudication turn (above). After a round, the loop SHALL **reconvene** a fresh panel **iff** all of:
(a) the round accepted at least one `blocking` issue, (b) the specification's normative content changed as a
result (measured by the SPEC-008 `normativeHash` over Requirements + Design, so a no-op "accept" does not
trigger a pointless round), and (c) the current round number is less than 3. Otherwise the loop SHALL
**converge** and stop. A dismiss-only round (no blocker accepted) SHALL NOT reconvene — re-review of an
unchanged draft would reproduce the same issues and never terminate. The round number, the reconvene/converge
decision, and the reason SHALL be traced and emitted (`panel.round-complete { round, applied, dismissed,
reconvened }`).

#### Scenario: Accepting a blocker on a changed spec reconvenes
- **WHEN** an adjudication round accepts a blocking issue and the normative hash changes, and the round
  number is below the cap
- **THEN** a fresh panel is convened on the revised draft for the next round

#### Scenario: A dismiss-only round converges
- **WHEN** an adjudication round dismisses every issue (accepts no blocker, so the normative hash is
  unchanged)
- **THEN** the loop converges and does not reconvene

#### Scenario: The round cap halts the loop
- **WHEN** three rounds have run
- **THEN** the loop stops regardless of remaining issues
- **AND** the convergence result records that the cap was reached, so the human sees it at approval

### Requirement: Accept-or-justify on blocking issues
`capability: review-panel` · `delta: ADDED (feat/spec-035-agent-adjudicated-review)`

For every `blocking` issue, the author SHALL either accept-and-apply it or dismiss it **with a non-empty
rationale**; a blocking issue left without a disposition SHALL be treated as an adjudication failure for that
round (the coordinator re-prompts the author for the missing dispositions, up to a small retry bound, before
surfacing the panel as `failed`). A dismissed **blocking** issue SHALL be carried into the convergence result
as an **unresolved blocker** and surfaced prominently to the human at the approval step. `suggestion` and
`question` issues MAY be accepted or dismissed at the author's discretion and do not gate anything.

#### Scenario: A dismissed blocker is surfaced, not dropped
- **WHEN** the author dismisses a blocking issue with a rationale
- **THEN** the issue is recorded as an unresolved blocker on the convergence result
- **AND** the human approval view lists it prominently with the author's rationale

#### Scenario: A blocking issue with no disposition fails the round
- **WHEN** the author returns dispositions that omit a blocking issue
- **THEN** the coordinator re-prompts for the missing disposition
- **AND** if still unresolved after the retry bound, the panel is marked `failed` and the review gate is not
  satisfied

#### Scenario: Suggestions never gate
- **WHEN** the only outstanding issues are `suggestion` or `question` severity
- **THEN** the loop may converge regardless of their disposition

### Requirement: The human's single governed action is approval
`capability: spec-lifecycle` · `delta: MODIFIED (feat/spec-035-agent-adjudicated-review)`

The review gate that guards `draft → in-review` (SPEC-024, `approveDraft`) SHALL be satisfied by
**adjudication convergence** for the current draft, tracked in durable state — not by bare panel completion.
On convergence, the coordinator SHALL **auto-run the gated `draft → in-review` promotion**; if a
machine-checkable precondition fails (`spec.malformed` well-formedness or `spec.branch-mismatch`), the
coordinator SHALL surface that error for a human/author fix rather than silently blocking, and SHALL NOT
advance. The human's only governed decision SHALL be `in-review → approved` (the existing second-human /
solo-flagged gate from SPEC-024) or **send-back** (which re-opens authoring and clears the converged-review
state so a fresh loop is required). The approval view SHALL present the consolidated adjudication report:
issues raised per reviewer, applied vs. dismissed with rationale, unresolved blockers flagged, and the
cumulative diff.

#### Scenario: Convergence auto-promotes to in-review
- **WHEN** the auto-review loop converges and the spec is well-formed on its declared branch
- **THEN** the coordinator runs the gated promotion and the card rests in `in-review`
- **AND** the review gate for this draft is satisfied in durable state

#### Scenario: A failing precondition surfaces instead of promoting
- **WHEN** the loop converges but the spec is malformed or `HEAD` is not the spec's branch
- **THEN** the coordinator emits `spec.malformed` / `spec.branch-mismatch` and leaves the spec in `draft`
- **AND** does not advance until the condition is fixed

#### Scenario: The human approves or sends back
- **WHEN** a converged spec rests in `in-review`
- **THEN** the human may approve it (`in-review → approved`) or send it back
- **AND** send-back re-opens authoring and clears the converged-review state, requiring a fresh loop before
  the spec can return to `in-review`

### Requirement: Adjudicator independence
`capability: review-panel` · `delta: ADDED (feat/spec-035-agent-adjudicated-review)`

Because the `spec-author` now judges critiques of its own draft, the coordinator SHALL resolve the author's
concrete model at adjudication time and compare it to the reviewers' resolved models. If the author's model
matches **any** reviewer's model, the coordinator SHALL emit and trace `panel.adjudicator-model-collision {
panelId, model, reviewerRole }` and proceed — the collision is a **warning, not a gate** (the reviewers
remain cross-model against each other, so adversarial pressure survives; hard-blocking would strand panels
when the registry offers few distinct capable models). The default agent roster SHOULD be configured so the
author and both reviewers resolve to three pairwise-distinct models.

#### Scenario: Author sharing a reviewer's model is warned, not blocked
- **WHEN** the resolved author model equals a reviewer's resolved model
- **THEN** the coordinator emits `panel.adjudicator-model-collision` and continues the adjudication
- **AND** the collision is recorded in the trace

#### Scenario: A distinct-model roster raises no collision
- **WHEN** the author and both reviewers resolve to three pairwise-distinct models
- **THEN** no `panel.adjudicator-model-collision` is emitted

### Requirement: Reviewer independence and auditability are preserved
`capability: review-panel` · `delta: MODIFIED (feat/spec-035-agent-adjudicated-review)`

This change SHALL NOT weaken the adversarial guarantees of SPEC-007: the two (or more) reviewers SHALL still
run in parallel via `dispatchAsync`, blind to each other's output, read-only (`edit: deny`, `bash: deny`),
on pairwise-distinct models. The full adjudication history SHALL be auditable: every round, every
disposition with rationale, every unresolved blocker, and the convergence reason SHALL be written to the
append-only trace before the human sees the approval view, and the review-gate state SHALL be reconstructable
from the trace on coordinator restart (extending `reconstructReviewGate()`).

#### Scenario: Reviewers remain blind, parallel, read-only, distinct
- **WHEN** a round convenes its panel
- **THEN** the reviewers run in parallel, are not shown each other's critiques, cannot write, and resolve to
  pairwise-distinct models

#### Scenario: The review loop reconstructs across a restart
- **WHEN** the coordinator restarts after a loop converged for a draft
- **THEN** the converged-review gate for that draft is rebuilt from the trace
- **AND** the spec does not require a fresh loop solely because of the restart

## Design

### Architectural decision

Adjudication becomes an **agent turn owned by the coordinator**, wrapped in a bounded loop. The panel-run
machinery (SPEC-007 `convenePanel` / `ingestReviewerMessage` / `maybeCompletePanel`) is reused unchanged for
the adversarial half; what changes is what happens *after* a panel completes. Instead of parking on human
clicks, the coordinator dispatches a `spec-author` adjudication turn, parses a structured disposition,
applies accepts through the author's existing write path, decides reconvene-vs-converge by the SPEC-008
normative hash, and — on convergence — drives the existing SPEC-024 gate itself. The human is moved from the
issue level to the specification level: one approval, over a consolidated report.

### Target architecture

```
convenePanel(specId)                        [SPEC-007, reused]
    └── reviewers run parallel → panel.issue / panel.agreed → panel.complete
            │
            ▼
adjudicateWithAuthor(panel)                 [NEW — replaces human adjudicateIssue path]
    ├── zero issues raised → converge immediately (nothing to adjudicate)
    ├── build adjudication prompt: working spec + grounding digest + all issues (severity, agreed marks)
    ├── resolve author model; compare to reviewer models → panel.adjudicator-model-collision (warn)
    ├── dispatchAsync { agent: "spec-author", parts:[prompt] } → await turn
    ├── parse dispositions (fenced json, reuse the review-panel parser discipline)
    ├── enforce accept-or-justify on blockers (re-prompt on gaps, bounded)
    ├── apply accepts (author edits working file); trace review.adjudicate per issue; emit panel.disposition
    └── return { applied[], dismissed[], unresolvedBlockers[], normativeHashAfter }
            │
            ▼
reviewLoop(specId)                          [NEW — the bounded orchestrator]
    ├── round = 1..3
    ├── reconvene iff (accepted a blocker) ∧ (normativeHash changed) ∧ (round < 3)
    ├── else converge → mark convergedReviews.add(specId) [replaces completedReviews semantics]
    ├── emit panel.round-complete; on convergence emit review.converged { rounds, unresolvedBlockers }
    └── auto-run approveDraft(specId) → in-review (or surface spec.malformed / spec.branch-mismatch)

review view (packages/client/src/screens/review-generation.tsx)   [MODIFIED]
    ├── live: round-by-round progress (reviewers → adjudicating → applied/dismissed → next round)
    └── on convergence: consolidated report — per-reviewer issues, applied vs dismissed + rationale,
        unresolved blockers flagged, cumulative diff, single Approve / Send-back control
```

### Interfaces and contracts

**New / changed ops (client → coordinator):**
```typescript
// start the whole loop for a draft (supersedes a bare convenePanel as the cockpit entry point)
{ type: "reviewSpec", specId: string, reviewers?: Array<{ role: string; instanceId?: string }> }

// send a converged/in-review spec back to authoring (clears converged-review state)
{ type: "sendBackReview", specId: string, note?: string }
```
`convenePanel` and `adjudicateIssue` remain in the coordinator as the mechanism `reviewSpec` orchestrates;
the human `adjudicateIssue` command path is retired from the UI (kept internally as the author-driven apply).

**New domain events (coordinator → client):**
```typescript
{ type: "panel.adjudicating", panelId: string, specId: string, round: number }
{ type: "panel.disposition", panelId: string, issueId: string, action: "accept" | "dismiss", rationale: string, actor: "spec-author" }
{ type: "panel.round-complete", panelId: string, specId: string, round: number, applied: number, dismissed: number, reconvened: boolean }
{ type: "panel.adjudicator-model-collision", panelId: string, reviewerRole: string }
{ type: "review.converged", specId: string, rounds: number, unresolvedBlockers: Array<{ issueId: string; section: string; text: string; rationale: string }> }
```
These extend the `DomainEvent` union in `@arke/contracts/src/events.ts`. The collision event carries only the
reviewer **role** to the client — the concrete colliding **model** is written to the trace (`panel.adjudicator-model-collision`)
host-side only, preserving the SPEC-005 rule that vendor model ids never cross to the client.

**Adjudication disposition (author → coordinator), parsed from the turn's final fenced json:**
```typescript
type Disposition = { issueId: string; action: "accept" | "dismiss"; rationale: string };
```
The adjudication prompt is **versioned** alongside the coordinator source (like the SPEC-007 issue-extraction
prompt), and its version is logged with each `panel.adjudicating` event.

**Gate state:** the durable `completedReviews` set is superseded by `convergedReviews` (a draft is gate-eligible
only after a loop *converged*, not after a panel merely *completed*). `reconstructReviewGate()` rebuilds it
from `review.converged` trace records; legacy `review.complete` records are treated as non-converged (they
predate agent adjudication and require a fresh loop).

### Cross-cutting

- **Design template:** the round-progress and consolidated-report surfaces follow the `arke-design` skill
  (`.claude/skills/arke-design/`) — neutral tokens, Geist, Lucide; do not re-derive styling.
- **Security / governance (NFR-1/7):** no `status`/`column` is written from the client; the loop drives the
  server-side SPEC-024 gate, which still rejects illegal transitions for all callers; send-back clears gate
  state fail-closed. Reviewers stay `edit: deny` / `bash: deny`; a reviewer write attempt still traces
  `policy.violation`.
- **Auditability (NFR-2):** every round, disposition, rationale, unresolved blocker, collision warning, and
  convergence reason is traced before the human sees the approval view; the adjudication prompt version is
  logged per round.
- **Resilience (NFR-8):** a reviewer error still does not abort a round (SPEC-007); if adjudication itself
  fails after the retry bound, the round is `failed`, the gate is not satisfied, and the human is shown the
  failure — never a silent pass. The bounded loop guarantees termination.
- **Multi-project scoping (SPEC-018):** the loop, its sessions, and the grounding digest are per active
  project context.

### Testing
- **Unit (loop):** blocker-accepted + normative-hash-changed reconvenes; dismiss-only converges; cap halts at
  3; convergence sets `convergedReviews` and auto-runs the gate; a converged-but-malformed spec surfaces
  `spec.malformed` and stays `draft`.
- **Unit (adjudication):** every issue gets a disposition; accept-or-justify enforced (missing blocker
  disposition re-prompts, then fails); dismissed blocker carried as unresolved; suggestions never gate;
  disposition parse recovers from prose the way the SPEC-007 issue parser does.
- **Unit (independence/gate):** author↔reviewer model collision emits `panel.adjudicator-model-collision`
  and still proceeds; distinct roster raises none; `reconstructReviewGate()` rebuilds `convergedReviews` from
  `review.converged`; legacy `review.complete` does not satisfy the gate.
- **Integration (MockAdapter):** a draft with seeded reviewer issues runs the loop end-to-end — round 1
  applies a blocker → reconvenes → round 2 dismiss-only → converges → auto-promotes to `in-review`; the
  human then approves; send-back clears the gate and requires a fresh loop.
- **Manual:** convene review on a real draft with two live reviewers + the author; watch the rounds; approve
  from the consolidated report; confirm the human never triaged an individual issue.

### Definition of done
The author adjudicates every panel issue with traced dispositions; the bounded loop reconvenes on a
blocker-driven material change and converges otherwise (cap 3); accept-or-justify holds on blockers with
dismissed blockers surfaced at approval; the review gate keys on convergence and auto-promotes to
`in-review`, leaving the human a single approval (or send-back); adjudicator-model collision is warned and
traced; reviewer independence and full auditability are preserved; the suite is green; a non-author reviewer
has signed off.

## Decision log

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The `spec-author` self-adjudicates (not a separate editor agent) | Matches the intent ("the spec writer reviews the results"); keeps the write path singular (SPEC-007 #4); independence is protected by the model-distinctness warning + full disposition audit rather than a new role |
| 2 | Bounded auto-loop, cap 3 rounds | Reviewers can always find *something*; an unbounded loop never terminates. Three rounds is enough to converge on real blockers while capping token spend; the human is the backstop for anything unresolved at the cap |
| 3 | Reconvene only on (blocker accepted ∧ normative hash changed) | A dismiss-only round changes nothing, so re-review would reproduce the same issues forever; gating reconvene on an actual normative change (SPEC-008 hash) guarantees progress and termination |
| 4 | Accept-or-justify on blockers, not must-apply-all | A reviewer can be wrong; forcing application of a mistaken blocker degrades the spec. Requiring a recorded rationale + surfacing dismissed blockers to the human preserves rigour without blind obedience |
| 5 | Model collision is a warning, not a gate | The reviewers stay cross-model against each other, so adversarial pressure survives even if the author shares one reviewer's model; hard-blocking would strand panels on a thin registry. Default roster is made distinct to avoid the warning in practice |
| 6 | Gate keys on *convergence*, and convergence auto-promotes to in-review | Delivers the core intent — "humans only approve." All `draft → in-review` preconditions are machine-checkable; the one genuinely human judgement is the governance approval at `in-review → approved` |
| 7 | Legacy `review.complete` does not satisfy the new gate | Those panels were never agent-adjudicated; honouring them would let a pre-change draft skip the new loop |

## Open questions
- Should the human be able to **override a single disposition** from the report (e.g. force-apply a blocker
  the author dismissed) without a full send-back? Deferred: send-back is the v1 lever; a per-issue override
  is a later affordance if the report shows it is frequently needed.
- Should the adjudication prompt receive the reviewers' **full prose analysis** or only the structured
  issues? Starting with structured issues (+ agreement marks); revisit if the author's dispositions miss
  nuance that lived only in the prose.
- Is a **3-round cap** right, or should it be per-project configurable? Fixed at 3 for v1; promote to config
  if projects diverge.
